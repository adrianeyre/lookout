# V2: the real Host, on a disposable VM — findings

**Scope issue:** #74 · **Date:** 25 November 2026 · **Status:** done; the VM was destroyed at 22:12 GMT on 25 November 2026.

Hypotheses: [H2](../../product-requirements-document/pen-testing.md#h2-the-socket-proxy-hands-docker-to-every-process-on-the-hosts-loopback--critical), [H14](../../product-requirements-document/pen-testing.md#h14-host-root-reads-follow-symlinks--low). Probe: [`pen-test/v2/probe.sh`](../../../pen-test/v2/probe.sh), run inside the VM as root, once per configuration, from the shipped `compose.yaml` and `compose.socket-proxy.yaml` with only the Image swapped for the round's (`lookout:pen-test`). It needs a real Linux kernel, so it is not in `pnpm test` or `pnpm pen-test:probe`; its deployment-side partners are `p1-proxy.probe.ts` and `r1-host-root.probe.ts`. Every secret in it is made up and carries `PEN-TEST-FAKE`.

## The VM

A throwaway [Lima](https://lima-vm.io) VM on the Tester's machine (`limactl start --name=lookout-v2 template:docker-rootful --mount-none`): Ubuntu 26.04.1 LTS, Linux 7.0.0 (aarch64), Docker 29.10.1 rootful, no host directory mounted. Never a Host in use. The probe made a Host owner, `owner` (UID 1000, the first account on most Linux Hosts), with a made-up `~/.ssh/id_ed25519` and `~/.docker/config.json`, both `0600`; an unprivileged local user, `pentest-nobody`, outside the docker group; a service on the Host's loopback only (`127.0.0.1:9109`, standing in for a database or an admin panel); and a victim Container with a made-up `API_TOKEN` and a named volume.

It ran twice: on the round's Image **before the fixes** (main at `b6f0e6d` plus the probes) and **after** them (`a71d38b`). Every proof was read-only: one file, one listing or one `GET`. Then the VM was destroyed (`limactl delete --force lookout-v2`), and `limactl list` reported no instance.

## Findings

V2 found nothing that was not already filed by another scope issue: it proved #101 (P1, critical) and #106 (R1, high) on a real kernel and Docker, and found host networking reaching the Host's loopback, which is ADR-0003's documented decision. **No new finding issue was filed.** Both findings were then fixed, and the second run on the same VM verified the fixes there as well.

## Load and reach

The VM had no host directory mounted. Lookout in it bound to `127.0.0.1`, and every probe request went to the VM's own loopback or socket. Setting the VM up pulled Ubuntu and Docker packages and the socket proxy's pinned Image; no probe request left the VM. One request at a time; nothing in parallel.
