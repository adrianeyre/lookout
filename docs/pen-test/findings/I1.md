# I1: deployment configuration — findings

**Scope issue:** #70 · **Date:** 25 November 2026 · **Status:** done; findings fixed and verified 25 November 2026. In-process probes, and deployment probes in both configurations, run before and after the fixes.

Hypotheses: [H10](../../product-requirements-document/pen-testing.md#h10-lookout-binds-every-interface-when-asked-and-says-nothing--low). Probe tests: [`apps/server/src/pen-test/probes/i1-configuration.test.ts`](../../../apps/server/src/pen-test/probes/i1-configuration.test.ts), which runs in `pnpm test`, and [`i1-deployment.probe.ts`](../../../apps/server/src/pen-test/probes/i1-deployment.probe.ts) against the deployment in the configuration that is running (`pnpm pen-test:probe`). Every secret in them is made up.

"In-process" means the real `main.ts` started in a child process with `net.Server#listen` stubbed to report success **without binding anything**, Docker pointed at a socket that does not exist and the fixture Host root, so only its startup log is read; or `loadConfig` called directly; or the shipped `compose.yaml`, `compose.socket-proxy.yaml` and `Dockerfile` read as text. "The round's Image" is `lookout:pen-test`, built from the round's commit by `pnpm pen-test:up`, inspected with one-off `--network none` runs and no socket. None of these depend on the configuration unless the row says so.

### #122 (F-I1-1): Lookout binds every interface, or a public address, when asked, and says nothing

- **Severity: low.** The PRD's opening estimate for H10. Hygiene: a documented instruction (README, ADR-0008) that the code neither enforces nor repeats.
- **Rule broken:** PRD, "Configuration fails closed: … a public bind address, are refused or warned at start"; ADR-0008 ("must never be exposed directly to the public internet").
- **Steps:** start Lookout with `LOOKOUT_BIND_ADDRESS=0.0.0.0`, `::` or a public address such as `203.0.113.7`; read the startup log.
- **Observed:** only `Server listening at http://…` lines at info level. **Expected:** a warning naming `LOOKOUT_BIND_ADDRESS` (or a refusal), at start, for `0.0.0.0`, `::` and any address that is not loopback, private (RFC 1918, ULA), link-local or CGNAT/Tailscale (`100.64.0.0/10`).
- **Impact:** with `network_mode: host`, a public interface puts sign-in (and H3's cost) in front of the internet with nothing in the log to notice by.
- **Test that would have caught it:** `I1 H10 › warns or refuses at start when LOOKOUT_BIND_ADDRESS is 0.0.0.0` (and `::`, `203.0.113.7`); deployment: `I1 H10: the round's Image at start › warns or refuses when bound to 0.0.0.0`.

### #123 (F-I1-2): Lookout's own service drops no capability, allows new privileges and has a writable root, unlike its proxy

- **Severity: low.** Defence in depth that the proxy's service has and Lookout's lacks. Mitigated today: as `node` no capability is effective, the Image has no setuid file and root owns the code. It matters when the README's `user: "0:0"` is used, and in the socket-proxy configuration, where a compromised Lookout is meant to hold only the allowlist.
- **Rule broken:** PRD severity table, "a boundary has no defence in depth"; ADR-0011's intent that a compromised Lookout gets no more than the allowlist.
- **Steps:** `docker inspect lookout` in either configuration; `grep ^Cap /proc/self/status` in the Container, as `node` and as root.
- **Observed:** `CapDrop` empty, `SecurityOpt` empty, `ReadonlyRootfs false`; bounding set `a80425fb`; as root all effective, `NET_RAW` in the Host's network namespace. **Expected:** `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `read_only: true` (with a `tmpfs` for `/tmp` if anything needs it), as on `docker-proxy`; the README's root option says which capability it then needs (`DAC_READ_SEARCH`) rather than all of them.
- **Impact:** code execution in Lookout run as root gets raw sockets on the Host's network and can write its own Image layer. Small while it runs as `node`.
- **Test that would have caught it:** `I1: Lookout's own service in compose.yaml › drops every capability, forbids new privileges and runs on a read-only root`; deployment: `I1: Lookout's own Container … › drops every capability, forbids new privileges, runs read-only, with a memory limit` (its memory half is X1's).

### #124 (F-I1-3): A valid Argon2id hash of any cost is accepted, down to 8 KiB and one pass

- **Severity: low.** Hygiene: `pnpm hash-password` always writes a sound hash; this needs a hash made elsewhere.
- **Rule broken:** PRD, "Configuration fails closed: … weak values … refused or warned at start"; ADR-0008's Argon2id as the defence in depth behind the network.
- **Steps:** start with `LOOKOUT_PASSWORD_HASH='$argon2id$v=19$m=8,t=1,p=1$…'`.
- **Observed:** accepted silently. **Expected:** a hash below OWASP's baseline (19 MiB with 2 passes, or an equivalent `m`/`t` trade) is refused or warned at start, naming the variable and never echoing the hash.
- **Impact:** whoever reads Lookout's environment (a docker-group user; H2's loopback callers with the proxy) can try passwords about 2,000 times faster than at the baseline.
- **Test that would have caught it:** `I1: configuration fails closed — weak values › warns or refuses an Argon2id hash far below the OWASP baseline (m=8, t=1)`.

## Load and reach

No request left the pen-test deployment, and the in-process probes bound no port: `listen` is stubbed, Docker is a socket that does not exist, and the one-off runs of the round's Image use `--network none`. The deployment probes only inspect and `exec` inside the throwaway daemon, run the round's Image there with `--network none`, and render `compose.yaml` with `docker compose config`, which starts nothing. Nothing was run in parallel.
