## Findings to file

### #125 (F-I2-1): `main` and `v*` tags have no rules, so one write token publishes an Image to every Host

- **Severity: medium.** A boundary with no defence in depth: between a write token and the Image every Host pulls, nothing stands.
- **H entry:** H12. **Configuration:** both (it is the delivery path for both).
- **Rule broken:** PRD, H12 ("the rules on `main` and on tags"); ADR-0009 and the v1 review rely on CI passing before anything is published, which nothing enforces for a direct push.
- **Steps:** `gh api repos/adrianeyre/lookout/branches/main/protection` → `404 Branch not protected`; `gh api repos/adrianeyre/lookout/rulesets` → `[]`. Then `actions/permissions`: `sha_pinning_required: false`; `vulnerability-alerts`: disabled.
- **Observed:** no rules on `main` or `v*` tags; GitHub does not enforce SHA pinning; Dependabot security alerts are off. **Expected:** a ruleset on `main` (pull request required, CI's checks required, no force-push or deletion) and on `v*` (creation, update and deletion restricted, so only the release workflow's token or the owner makes them); SHA pinning required; vulnerability alerts on.
- **Impact:** one leaked token, or one mistaken push, goes straight to `:edge` and, with a `feat:`/`fix:` commit, to `:1.0` on every Host.
- **Test that would have caught it:** none in the tree can: it is GitHub's settings. Recorded here, and re-read with `gh api` when the round is verified.

### #126 (F-I2-2): Hosts pull the moving `:1.0` tag, and nothing signs or verifies what they pull

- **Severity: medium.** A control (provenance and SBOM) is weaker than it reads: it is attached but nothing checks it, and the tag Hosts are told to use moves.
- **H entry:** H12. **Configuration:** both.
- **Rule broken:** PRD, H12; README ("`:1.0` … Recommended").
- **Steps:** read `compose.yaml:10`, `.github/dependabot.yml` (ignore `ghcr.io/adrianeyre/lookout`), `.github/workflows/image.yml` (`provenance: mode=max`, `sbom: true`, no attestation, no `id-token: write`), and the README.
- **Observed:** `image: ghcr.io/adrianeyre/lookout:1.0`; no signature or attestation; no verification step for the operator. **Expected:** every pushed Image attested (`actions/attest-build-provenance`, with `id-token: write` and `attestations: write` on the Image job alone), the README telling the operator how to verify one (`gh attestation verify oci://ghcr.io/adrianeyre/lookout:1.0 --repo …`) and how to pin by digest, and the moving tag's acceptance recorded with an end date.
- **Impact:** whoever can push to GHCR (F-I2-1, or a stolen token) replaces `:1.0` for every Host on its next pull, with nothing to tell a real Image from another.
- **Test that would have caught it:** `I2: what Hosts pull (H12) › signs or attests every Image it pushes, and the README says how to verify one`, and `› pins Lookout's own Image by digest in compose.yaml, or lets Dependabot move it`.

### #127 (F-I2-3): semantic-release and its dependencies run with issues and pull-requests write they don't need

- **Severity: low.** Hygiene: a broader token than needed, and an accepted risk nothing records.
- **H entry:** H12. **Configuration:** both.
- **Rule broken:** PRD, H12 ("`pnpm install` beside a write token"); least privilege as the workflows otherwise apply it.
- **Steps:** read `release.yml`'s `release` job and `.releaserc.json`.
- **Observed:** `contents`, `issues` and `pull-requests: write` for every dependency of semantic-release; `@semantic-release/github` comments on every included issue and pull request. **Expected:** comments off (`successComment: false`, `failComment: false`, `releasedLabels: false`), `issues`/`pull-requests: write` dropped, and `contents: write` recorded as accepted (ADR-0009, or the release section of the README) with when it stops being true.
- **Impact:** a compromised semantic-release dependency could also edit issues and pull requests (including closing the tracking issue that holds the release gate open).
- **Test that would have caught it:** `I2: what runs beside the release token › grants semantic-release only contents: write, with comments on issues and pull requests turned off`.

### #128 (F-I2-4): The Project Website has no Content Security Policy

- **Severity: low.** Defence in depth on a page that holds no session and no secret; the changelog's escaping is sound today.
- **H entry:** H13 (website half). **Configuration:** static (the Project Website).
- **Rule broken:** PRD, H13 ("the Project Website may have none … to confirm").
- **Steps:** look for `http-equiv="Content-Security-Policy"` in `site/index.html`, `site/404.html` and `site/dist/index.html`.
- **Observed:** none. **Expected:** a meta CSP on every page: `default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'` (plus `img-src 'self' data:` and `style-src 'self'` as the page needs; `frame-ancestors` cannot be set by meta).
- **Impact:** if the changelog renderer ever regresses, a pull-request title runs script on the Project Website.
- **Test that would have caught it:** `I2 H13 (website half): the Project Website has a Content Security Policy › sets a CSP on every page…`.

### #129 (F-I2-5): The site publishes every PNG in `docs/images`, and no test pins the set

- **Severity: low.** Disclosure risk, none today: every image now published was read and shows fixtures only.
- **H entry:** none (the PRD's "Good and to confirm": "every published image is read for real Host data, and the set is pinned by a test"). **Configuration:** static.
- **Rule broken:** PRD, "Good and to confirm" (`site/build.ts` … "the set is pinned by a test"), which is not true.
- **Steps:** read `verbatimFiles()` in `site/build.ts`; search the tests for the list.
- **Observed:** the set is whatever `readdir(docs/images)` returns. **Expected:** a list in `site/build.ts` (`PUBLISHED_IMAGES`), with a test that fails when `docs/images` or `site/public` holds a file not on it, so a new image is published only after someone has read it.
- **Impact:** a screenshot taken against a real Host (hostnames, Container names, LAN addresses) is published on the next Pages run.
- **Test that would have caught it:** `I2: the images the site publishes › publishes a pinned list of images…`.

### #130 (F-I2-6): Nothing can show the vendored Stageshow kit is unmodified

- **Severity: low.** Supply-chain hygiene for code that only the Project Website runs.
- **H entry:** none (PRD, scope of I2: "the vendored `site/stageshow` kit"). **Configuration:** static.
- **Rule broken:** `site/stageshow/README.md`: "`kit/` is copied as published, **unmodified**", which nothing checks.
- **Steps:** look for a hash of `site/stageshow/kit/` in the tree.
- **Observed:** version and commit are recorded; no hashes; no tool updates it. **Expected:** `site/stageshow/SHA256SUMS` taken from the named upstream commit, and a test that hashes `kit/` against it, so an edit, or a copy from elsewhere, fails `pnpm test`.
- **Impact:** a change to the kit (by mistake, or in a pull request that touches many files) reaches the Project Website unnoticed.
- **Test that would have caught it:** `I2: the vendored Stageshow kit › can show the copy is unmodified…`.

## The owner's settings (25 November 2026)

At the owner's request (25 November 2026), applied with `gh api`:

- ruleset **28103638** on `main`: no deletion, no force-push;
- ruleset **28103640** on `v*` tags: no update, no deletion;
- vulnerability alerts on;
- Actions `sha_pinning_required: true`.

Not applied: requiring pull requests and status checks on `main`, and restricting who creates `v*` tags. GitHub Actions cannot be a ruleset bypass actor on a personal repository, and semantic-release pushes its release commit and creates its tag with `GITHUB_TOKEN`, so either rule would stop every release. That residual (a write token can still push to `main` fast-forward, and create a `v*` tag) is accepted until 25 February 2027 (the next round), or until releases move to a GitHub App token, which can be a bypass actor.

Still for the owner to look at:

1. GHCR: `ghcr.io/adrianeyre/lookout`'s package settings: which repositories have Actions access, and that no other user, team or PAT can write.
2. The `github-pages` environment, once Pages is enabled: deployment from `main` only.
3. The public `adrianeyre/lookout` repository (empty today, with one ruleset on `main`): if releases or the Image move there, every row above applies to it.
