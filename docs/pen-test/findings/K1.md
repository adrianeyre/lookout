## Findings filed

### #79 (F-K1-1): The environment reveal serves Lookout's own session secret and password hash

- **Severity: high.** A signed-in session gets more than ADR-0005 allows, through an action on `lookout.self` in all but name. Holding the secret lets someone mint sessions offline that outlive a password change (A1's half), and the hash can be attacked offline.
- **Rule broken:** PRD, "A secret is shown only when asked for, one at a time, wherever it sits: … Lookout's own configuration". FR-26 and ADR-0005 put `lookout.self` out of reach of what a session may do. ADR-0008 relies on the secret staying secret.
- **Steps:** sign in, then `GET /api/containers/lookout/env/LOOKOUT_SESSION_SECRET` and `…/LOOKOUT_PASSWORD_HASH`.
- **Observed:** `200` with each value. **Expected:** `403`, refused like a Container Action on `lookout.self`, or masked.
- **Impact:** one signed-in moment (a stolen cookie, or H6) becomes durable access that survives a password change.
- **Test that would have caught it:** `K1 H1 (reveal half) › refuses to reveal any environment value of a lookout.self Container`.

### #91 (F-K1-2): Secrets in the command, entrypoint, labels and mounts are shown in full, and labels go out in every stream event

- **Severity: medium.** A control (FR-20's one-at-a-time, logged reveal) is weaker than the documentation says, because it covers only the environment.
- **Rule broken:** PRD, "A secret is shown only when asked for, one at a time"; FR-20.
- **Steps:** run a Container with `redis-server --requirepass X`, a `traefik…basicauth.users` label, a database-URL label and a bind mount whose source path holds a token. Then read `GET /api/containers/:id`, `GET /api/containers` and `/api/stream`.
- **Observed:** all of them in plain text. The labels are in every list and in every `containers` event to every open tab. **Expected:** values that look like secrets are masked and revealed one at a time and logged, as environment values are.
- **Impact:** credentials sit on screen and in every browser holding a stream, with no record of who saw them.
- **Test that would have caught it:** `K1 H8 › does not send secrets in the command, entrypoint, labels or mounts unasked` and `› does not put label secrets in every Container list`.

### #92 (F-K1-3): Node's and the proxy's error text reach the browser in a failed Container Action

- **Severity: low.** Disclosure to a signed-in user only.
- **Rule broken:** PRD, "Every refusal comes from a closed set … no Docker, proxy or Node text reaches a caller who didn't need it". FR-27 covers Docker's own message, not Node's or the proxy's.
- **Steps:** make the Engine unreachable mid-action (stop the proxy), or have the proxy refuse it, then POST any action.
- **Observed:** `502 {"error":"connect ECONNREFUSED 127.0.0.1:2375"}` and `502 {"error":"socket-proxy: request blocked"}`. **Expected:** Docker's `json.message` only (FR-27), and otherwise a fixed text such as "Docker could not complete the action".
- **Impact:** internal addresses and the proxy's identity are disclosed. Small.
- **Test that would have caught it:** `K1 H11 › never returns Node or connection error text from a failed Container Action`.

### #93 (F-K1-4): An over-long Container reference gets Fastify's 414, which echoes the path, even without a session

- **Severity: low.** A hygiene and disclosure issue: the refusal comes from outside the closed set, before the session hook.
- **Rule broken:** PRD, "Every refusal comes from a closed set"; "Refusals give nothing away".
- **Steps:** `GET /api/containers/<129 × a>`, with or without a cookie.
- **Observed:** `414 {"error":"Bad Request","code":"FST_ERR_MAX_PARAM_LENGTH","message":"'/api/containers/aaa…' is exceeding the max param length","statusCode":414}`. The route's own `CONTAINER_REF` bound of 128 is dead code above 100 characters. **Expected:** `404 {"error":"No such Container"}`, or `401` without a session.
- **Impact:** it reveals the framework and gets around the uniform 401, but holds no data.
- **Test that would have caught it:** `K1: over-long references › refuses an over-long reference with the same closed-set 404 as any other`.

## Load and reach

No request left the pen-test deployment: the deployment probes ran only against `127.0.0.1:7780` or inside its throwaway daemon, and its isolation probe (`e1-isolation.probe.ts`) passed in the same run, in each configuration. The in-process probes opened no socket beyond the app's own. The largest demonstration was one request at a time; nothing was run in parallel.
